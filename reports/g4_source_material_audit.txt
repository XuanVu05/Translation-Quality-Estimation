# G2 – Experimental Evaluation and Model Comparison

**Project:** Second Pair of Eyes – Reference-Free Critical Error Detection for English→German Machine Translation  
**Dataset:** WMT 2020 MQM English→German (`newstest2020`)  
**Evaluation phase:** Week 10  
**Status:** Completed with reporting caveats  
**Prepared from:** `dev_baseline_metrics.csv`, `dev_ablation_metrics.csv`, `test_point_metrics.csv`, `test_metrics_with_ci.csv`, `paired_difference_ci.csv`, and `test_predictions.csv`.

---

## 1. Purpose and scope of G2

G2 evaluates whether lightweight, CPU-feasible machine-learning models can rank machine-translated segments by their likelihood of containing a critical translation error, so that a human reviewer can inspect a limited subset first.

The experimental comparison includes:

1. Random ranking as a reference point.
2. A rule-based heuristic using source/target text characteristics.
3. Logistic Regression using TF-IDF and surface features.
4. Linear Support Vector Machine (Linear SVM) using the same base feature representation.
5. An ablation study examining the contribution of MT-system identity.

The operational evaluation emphasizes a fixed review budget of 20%. PR-AUC is also reported because it evaluates ranking quality across thresholds and is useful for an imbalanced binary classification problem. Precision@20%, Recall@20%, Lift@20%, and MCC@20% describe performance at the selected review budget.

This report records the supplied experimental outputs. It does not claim that the experiments establish generalization to unseen MT systems or that the model replaces human review.

## 2. Dataset, labels, and split used in evaluation

The model dataset contains 9,926 MT segment-level examples from seven MT systems and 130 documents. The primary label is `y_primary`, constructed from three distinct annotator votes: a segment is labelled Critical (`1`) when at least two annotators cast a serious-error vote; otherwise it is labelled Non-critical (`0`).

The document-level split used for Week 10 is:

| Partition | Rows | Documents | Positive samples |
|---|---:|---:|---:|
| Train | 6,797 | 90 | 803 |
| Dev | 1,554 | 20 | 218 |
| Test | 1,575 | 20 | 162 |
| **Total** | **9,926** | **130** | **1,183** |

Documents, rather than individual segments, are the grouping unit. The split audit found no document overlap between Train, Dev, and Test. The locked split hash recorded in the project audit is:

`780cd9f0b2b32042ad95f8e67318c03814fbe895e1f0ef8755da847e8d287ab`

The Test set contains 162 positive examples among 1,575 rows, giving a prevalence of approximately **10.29%**. Its 20% review budget is 315 segments (the integer cutoff used in the supplied predictions).

## 3. Models and feature configurations

### 3.1 Random ranking

Random assigns a random ranking to examples and provides a non-informative reference point. On Dev, the reported Random metrics are averaged over 100 rankings (seeds 42–141). The reported standard deviations describe variability across those Dev random runs.

On Test, the supplied evaluation uses one random ranking with seed `20261026`. Therefore, the Test Random point estimate and interval should not be interpreted as an average over repeated random rankings. This difference in protocol is a reporting limitation and should be stated explicitly.

### 3.2 Rule-based heuristic

The heuristic produces a ranking score from source/target text characteristics without fitting a supervised classifier. It is a necessary non-random baseline: the learned models must be compared not only with chance but also with a simple, transparent rule-based approach.

The precise heuristic formula should be described in the Methods section from the implementation in the repository. This results report does not infer additional rule details beyond the supplied evaluation outputs.

### 3.3 Logistic Regression and Linear SVM

The base feature representation comprises:

- Separate TF-IDF representations for source and target text.
- Word n-grams with `ngram_range=(1, 2)`.
- `max_features=30,000` for each vectorizer, `min_df=2`, and `sublinear_tf=True`.
- Twelve surface features derived from source and target text.

The twelve surface features recorded in the feature-provenance audit are:

1. Log-transformed source token count.
2. Log-transformed target token count.
3. Target/source token-count ratio.
4. Absolute token-count difference relative to source length.
5. Target/source character-length ratio.
6. Source digit count.
7. Target digit count.
8. Absolute digit-count difference.
9. Target uppercase ratio.
10. Target punctuation/symbol ratio.
11. Repeated-token count in target.
12. Empty-target indicator.

TF-IDF vectorizers and the feature scaler are fitted on the training data only during Dev evaluation, then applied to Dev using `transform`. The inspected baseline implementation does not use document identifiers, segment identifiers, MQM annotations, or labels as input features.

The baseline implementation uses class-weight balancing. The documented model settings are Logistic Regression with `C=1`, `max_iter=2000`, `random_state=42`, and Linear SVM with `C=1`, `max_iter=10000`. The model target is `y_primary`.

### 3.4 System-identity ablation

The ablation compares:

- `LR_Base`: TF-IDF source/target plus twelve surface features.
- `LR_Plus_System`: base features plus one-hot encoded MT-system identity.
- `System_Only`: system identity alone.

The encoder is fitted on Train and applied to Dev. The ablation is a diagnostic experiment: it measures whether system identity adds useful predictive information in this dataset. It does not demonstrate that a model will generalize to previously unseen MT systems.

## 4. Evaluation metrics

Let the top-ranked 20% of segments be the review queue.

- **PR-AUC:** area under the precision-recall curve; summarizes ranking performance over thresholds and is informative under class imbalance.
- **Precision@20%:** proportion of reviewed segments that are Critical.
- **Recall@20%:** proportion of all Critical segments captured within the review queue.
- **Lift@20%:** Precision@20% divided by the positive prevalence in the evaluated partition. A value above 1 indicates enrichment over selecting segments without ranking.
- **MCC@20%:** Matthews correlation coefficient after treating the top-20% queue as predicted positive and the remaining examples as predicted negative.
- **Positive samples in top 20%:** absolute number of Critical segments retrieved within the review budget.

For an operational interpretation, Precision@20% describes the concentration of critical errors in the queue, while Recall@20% describes how much of the total critical-error pool is captured by that queue. Neither metric alone describes all aspects of ranking quality.

## 5. Development-set baseline results

The Dev partition has 1,554 examples and a positive prevalence of **14.03%**. The following values are taken from `dev_baseline_metrics.csv`.

| Model | PR-AUC | Recall@20% | Precision@20% | Lift@20% | MCC@20% |
|---|---:|---:|---:|---:|---:|
| Random | 0.1435 | 0.1996 | 0.1399 | 1.00 | -0.0005 |
| HeuristicRules | 0.1777 | 0.3303 | **0.2315** | **1.65** | **0.1314** |
| LogisticRegression | **0.1961** | 0.2890 | 0.2026 | 1.44 | **0.0897** |
| LinearSVM | 0.1742 | 0.2752 | 0.1929 | 1.38 | 0.0758 |

Random results are means over 100 rankings; the corresponding standard deviations are in the source CSV. The heuristic and supervised model values are deterministic point estimates in the supplied file.

### 5.1 Interpretation

Logistic Regression achieves the highest Dev PR-AUC (0.1961), indicating the strongest overall precision-recall ranking among the listed methods on this partition. However, the heuristic has the highest Precision@20%, Recall@20%, and Lift@20%.

This distinction matters for the research objective. The objective is not simply to maximize a threshold-independent score; it is to prioritize segments under a fixed review budget. On Dev, the rule-based heuristic is more effective at the specific 20% cutoff, even though Logistic Regression has higher PR-AUC.

Linear SVM is below Logistic Regression on all five listed Dev metrics. These results support carrying Logistic Regression forward as the main learned model, while retaining the heuristic as a serious operational comparator.

## 6. Ablation study on Dev

The ablation outputs report 6,797 training rows and 1,554 Dev rows for each configuration. The base and system-augmented representations contain 58,150 and 58,157 features respectively.

| Configuration | PR-AUC | Recall@20% | Precision@20% | Lift@20% | MCC@20% | Critical in top 20% |
|---|---:|---:|---:|---:|---:|---:|
| LR_Base | 0.1961 | **0.2890** | **0.2026** | **1.4440** | **0.0897** | 63 |
| LR_Plus_System | **0.1991** | 0.2798 | 0.1961 | 1.3982 | 0.0805 | 61 |
| System_Only | 0.1568 | 0.2523 | 0.1768 | 1.2607 | 0.0527 | 55 |

### 6.1 Interpretation

Adding system identity produces a small PR-AUC increase, from 0.1961 to 0.1991. However, the system-augmented model performs worse on Recall@20%, Precision@20%, Lift@20%, and MCC@20%. It retrieves 61 Critical examples in the top 20%, compared with 63 for the base model.

The System_Only model is weaker than the text-based configurations, although it performs above the random reference on several measures. This indicates that system identity contains some dataset-specific signal, but it is not a substitute for source/target text features.

The ablation does not support retaining system identity as a default feature for the primary model when the operational target is top-20% review effectiveness. It also warns against claiming generalization to unseen MT systems: the system-identity feature explicitly relies on known system categories.

## 7. Final Test-set results

The Test partition contains 1,575 examples, including 162 Critical examples. The top-20% queue contains 315 segments. Values below are from `test_point_metrics.csv`; the corresponding confidence intervals are recorded in `test_metrics_with_ci.csv`.

| Model | PR-AUC | Recall@20% | Precision@20% | Lift@20% | MCC@20% |
|---|---:|---:|---:|---:|---:|
| Random | 0.1091 | 0.1975 | 0.1016 | 0.99 | -0.0021 |
| HeuristicRules | 0.1391 | 0.3086 | 0.1587 | 1.54 | 0.0920 |
| LogisticRegression | **0.1971** | **0.3148** | **0.1619** | **1.57** | **0.0972** |
| LinearSVM | 0.1676 | 0.2346 | 0.1206 | 1.17 | 0.0293 |

### 7.1 Operational interpretation at the 20% review budget

The Test prediction file contains 1,575 rows and four ranking-score columns (Random, HeuristicRules, LogisticRegression, and LinearSVM). Recomputing the top-315 selections from the prediction scores gives:

| Model | Critical examples in top 315 | Precision@20% |
|---|---:|---:|
| Random | 32 | 10.16% |
| HeuristicRules | 50 | 15.87% |
| LogisticRegression | **51** | **16.19%** |
| LinearSVM | 38 | 12.06% |

Logistic Regression retrieves 51 of the 162 Critical examples, compared with 50 for the heuristic. Thus, the absolute operational gain is one additional Critical segment in a queue of 315 items. The relative improvement in PR-AUC is more substantial than the difference in the fixed-budget queue.

The result supports a nuanced conclusion: Logistic Regression has the best point estimates on the Test metrics shown, but its practical advantage over the heuristic at the 20% cutoff is modest.

## 10. Threats to validity and reporting caveats

### 10.1 Different number of random rankings on Dev and Test

The Dev Random baseline averages 100 random rankings, whereas the Test Random baseline uses one random ranking (seed `20261026`). This does not invalidate the learned-model predictions, but it makes the random-baseline uncertainty treatment inconsistent across partitions. State this limitation explicitly. If computationally feasible, rerun the Test Random baseline over 100 fixed, documented seeds and report its mean and standard deviation. Do not replace the existing Test result silently; preserve both the original and supplementary result.

### 10.2 Limited operational difference between Logistic Regression and heuristic

Although Logistic Regression has the highest Test point estimates, it retrieves only one more Critical segment than the heuristic in the top 315. The paired bootstrap intervals for top-20% metrics include zero. Avoid claiming a demonstrated practical or statistically reliable top-20% advantage.

### 10.3 Generalization scope

The evaluation uses a document-disjoint split from the same WMT 2020 English→German dataset and the same seven MT systems. It supports claims about held-out documents within this dataset. It does not by itself establish transfer to other language pairs, years, domains, annotation schemes, or unseen MT systems.

### 10.4 Label uncertainty

The binary target is derived from three annotators and a two-vote threshold. This operationalizes the project's definition of Critical Error but does not eliminate disagreement or subjectivity in MQM annotation. The threshold sensitivity and qualitative error analysis should be discussed elsewhere in the report.

### 10.5 Confidence intervals

The bootstrap resamples documents as clusters, which is more appropriate than treating all segments as independent when segments within a document may be correlated. However, there are only 20 Test documents. The uncertainty estimates should therefore be interpreted with the limited number of independent document clusters in mind.

### 10.6 System-identity ablation

The system-identity ablation is informative about dataset-specific system effects. Since the evaluation split contains the same system categories across partitions, it is not an unseen-system generalization experiment.

## 11. Main findings

The experiments support the following findings:

1. The rule-based heuristic is a meaningful baseline and performs substantially better than the random ranking at the 20% review budget.
2. Logistic Regression achieves the strongest overall ranking performance among the tested methods, with the highest Dev and Test PR-AUC.
3. Linear SVM does not outperform Logistic Regression or the heuristic in the supplied point estimates.
4. Adding MT-system identity slightly increases PR-AUC on Dev but reduces all reported top-20% measures relative to the base Logistic Regression model.
5. On Test, Logistic Regression retrieves 51 Critical examples in the top 315, compared with 50 for the heuristic. The operational gain at this cutoff is therefore small.
6. Paired document-cluster bootstrap supports a positive PR-AUC difference between Logistic Regression and the heuristic, but does not establish a difference in the fixed-budget top-20% metrics.
7. The results justify a decision-support ranking system for prioritizing human review, not an autonomous translation-quality judge.

## 12. Recommended conclusion for the research report

> The experimental results show that a lightweight Logistic Regression model based on source/target TF-IDF representations and surface-level linguistic features can achieve stronger overall ranking performance than a rule-based heuristic on the held-out WMT 2020 English→German test documents, as reflected by PR-AUC. However, under the operational constraint of reviewing only the top 20% of segments, the improvement is marginal: Logistic Regression identifies 51 critical segments compared with 50 for the heuristic among 315 reviewed segments. Paired document-cluster bootstrap intervals support a positive PR-AUC difference but do not establish a reliable advantage in Recall@20%, Precision@20%, Lift@20%, or MCC@20%. The system should therefore be presented as a lightweight decision-support mechanism that helps prioritize human inspection, rather than as a replacement for human evaluation or as evidence of generalization to unseen MT systems.

# G3.6 – Báo cáo tổng kết tính tái lập

## 1. Mục đích

G3.6 tổng hợp các bằng chứng về khả năng tái lập của quy trình thực nghiệm cho bài toán phát hiện lỗi dịch thuật nghiêm trọng (Critical Error Detection – CED) trên bộ dữ liệu WMT 2020 MQM English–German.

# G4.1 – Qualitative Error Analysis of High-Ranked Non-Critical Predictions

## 1. Objective

This analysis investigates ten high-ranked development-set examples selected from the Logistic Regression baseline (LR_Base). All ten examples were assigned the primary label `y_primary = 0`, meaning that none met the project's operational definition of a Critical Error.

The purpose is not to establish that these translations are incorrect. Instead, the analysis examines why the model assigns high priority to segments that are not labelled as critical, and whether these cases reveal minor translation problems, stylistic weaknesses, annotation disagreement, or limitations of the MQM-based target label.

The analysis uses three complementary sources of evidence:

1. Original English source and German MT output.
2. MQM annotations that match the normalized target translation.
3. Context from adjacent segments where available.

No model was retrained, and no Test-set observations were used.

## 2. Evidence matching and validation

The ten selected cases were matched against the original MQM annotation file and the official original MT outputs.

| Audit item                             | Result |
| -------------------------------------- | -----: |
| Selected system-segment cases          |     10 |
| Candidate MQM annotation rows          |     47 |
| Target-matched annotation rows         |     42 |
| Target-unmatched annotation rows       |      5 |
| Cases with target-matched annotations  |  10/10 |
| Original MT mapping checks passed      |  10/10 |
| Development target matches original MT |  10/10 |
| Recomputed serious annotation rows     |      0 |
| Recomputed serious votes               |      0 |
| Cases with recomputed `y_primary = 1`  |      0 |

The five target-unmatched annotation rows were retained in a separate audit file. They were not used to extract annotated spans or support the primary qualitative interpretation. A target-unmatched annotation is not necessarily invalid; it may refer to another target variant associated with the same system-segment key.

The serious-error rule was independently reapplied:

- Severity must be `Major`.
- Category must start with `Accuracy/` or equal `Non-translation!`.
- Serious votes are aggregated by distinct rater.
- The primary label is positive when at least two raters provide a serious vote.

All ten cases remained negative under this rule.

## 3. Case-level qualitative analysis

### Case 1 – Online-B.1590, abcnews.363994

**Source**

" Court documents say the surgeon was leaving a Walmart store when he was confronted by an armed man and shoved into a van. They say he was tortured for hours before being returned to his car while unconscious. Surveillance video supports the chain of events. Investigators say Nkorina's wife was a client of the surgeon."

**MT output**

"Gerichtsdokumente besagen, dass der Chirurg ein Walmart-Geschäft verließ, als er von einem bewaffneten Mann konfrontiert und in einen Van geschoben wurde. Man sagt, er wurde stundenlang gefoltert, bevor er bewusstlos zu seinem Auto zurückgebracht wurde. Das Überwachungsvideo unterstützt die Ereigniskette. Die Ermittler sagen, Nkorinas Frau sei eine Klientin des Chirurgen gewesen."

**MQM evidence**

- Six target-matched annotation rows from two raters.
- Five candidate annotation rows did not match the normalized target.
- Matched categories include `Accuracy/Mistranslation` and `Style/Awkward`.
- All matched annotations have Minor severity.
- No target-matched Major annotation was found.

**Qualitative assessment**

The expression "Man sagt" is a relatively general rendering of "They say" and may weaken the connection to the preceding reference to court documents. The expressions "Walmart-Geschäft", "konfrontiert", "unterstützt" and "Klientin" were also marked by annotators.

These observations suggest lexical and stylistic weaknesses rather than a demonstrated critical change in the event sequence. The Major annotation found among the five target-unmatched rows must not be attributed to the current target.

**Interpretation:** A high-ranked example containing several minor annotation issues, but no target-matched evidence of a Critical Error.

### Case 2 – eTranslation.737, standard.co.uk.14516

**Source**

"Mac Miller death: Third man charged with drug offences"

**MT output**

"Mac-Miller-Tod: Dritter Mann wegen Drogendelikten angeklagt"

**MQM evidence**

- Three target-matched annotation rows.
- Three raters.
- All annotations use category `Style/Awkward`.
- Two annotations are Minor and one is Major.

**Qualitative assessment**

The compound "Mac-Miller-Tod" may sound compressed or awkward as a German headline. However, the Major annotation belongs to `Style/Awkward`, not to the project's critical category set.

This case demonstrates that severity alone is insufficient to determine whether a segment is a Critical Error. The category and severity must be considered together.

**Interpretation:** A stylistic issue with one Major annotation, but no operational Critical Error.

### Cases 3–9 – Seven MT systems translating the same source segment

**Source**

"Allen's family pays nearly $12,000 per year for Amari to attend the school, which made headlines earlier this year after Karen Pence took an art teaching job at the famously anti-LGBTQ institution."

These seven cases correspond to the same source document and segment, `cbsnews.302129`, `doc_id=10`, `seg_id=763`, but have different MT systems and outputs.

| Case | MT system                | LR_Base rank | Matched MQM evidence                  |
| ---: | ------------------------ | -----------: | ------------------------------------- |
|    3 | Online-B.1590            |            3 | Minor Style, Minor Accuracy, No-error |
|    4 | OPPO.1535                |            6 | Minor Fluency, Accuracy and Style     |
|    5 | Online-B.1590            |            8 | Minor Fluency, Accuracy and Style     |
|    6 | Huoshan_Translate.832    |            9 | Minor Fluency, Accuracy and Style     |
|    7 | eTranslation.737         |           10 | Minor Fluency, Accuracy and Style     |
|    8 | Tencent_Translation.1520 |           11 | Minor Fluency, Accuracy and Style     |
|    9 | Online-A.1574            |           13 | Minor Fluency, Accuracy and Style     |

**Qualitative assessment**

Several systems use constructions similar to:

"für Amari, um die Schule zu besuchen"

This construction is understandable, but may be less idiomatic than a formulation such as:

"damit Amari die Schule besuchen kann"

Another possible formulation is:

"für Amaris Schulbesuch"

The Online-B output also uses a more nominalized construction:

"für den Besuch der Schule durch Amari"

This is understandable but comparatively cumbersome.

The annotations repeatedly identify spans around "um", "was" and "um die Schule zu besuchen". This indicates that annotators noticed recurring fluency or stylistic weaknesses across different system outputs.

The Online-A output uses "Kunstlehrjob", which was marked as an Accuracy/Mistranslation Minor issue. This lexical choice deserves attention, although the annotation does not establish a critical semantic error.

**Interpretation**

The seven outputs show how different MT systems can produce different realizations of the same source segment while exhibiting similar minor fluency and style issues.

This group is especially useful for system-level comparison. However, these are seven system-segment observations, not seven independent source segments. They must not be counted as seven independent examples when discussing generalization.

### Case 5 – Online-B.1590, cbsnews.302129

**Source**

"According to WUSA, one of the boys allegedly covered Amari's mouth while another held her hands behind her back and a third took a pair of scissors to her dreadlocks."

**MT output**

"Laut WUSA bedeckte einer der Jungen angeblich Amaris Mund, während ein anderer ihre Hände hinter dem Rücken hielt und ein dritter eine Schere zu ihren Dreadlocks nahm."

**MQM evidence**

- Five target-matched annotation rows.
- Three raters.
- Categories include `Fluency/Grammar`, `Accuracy/Mistranslation` and `Style/Awkward`.
- All annotations have Minor severity.

**Qualitative assessment**

The expression "eine Schere zu ihren Dreadlocks nahm" appears to follow the English idiom "took a pair of scissors to her dreadlocks" quite literally. The German output communicates the presence of scissors but does not express the cutting action as directly as the English source.

A more explicit German formulation could be:

"... und ein dritter schnitt ihr mit einer Schere die Dreadlocks ab."

This is a useful example of a potentially overly literal translation. The MQM annotations identify the relevant phrase, but do not classify it as a Critical Error.

**Interpretation:** A minor translation-quality issue involving idiomatic meaning and natural expression, not a confirmed Critical Error.

### Case 10 – Huoshan_Translate.832, seattle_times.7755

**Source**

"Brown has been accused of sexual misconduct by two women. He was released by the New England Patriots last week after playing only one game. He's been dumped by three teams in the last six months."

**MT output**

"Brown wurde von zwei Frauen des sexuellen Fehlverhaltens beschuldigt. Er wurde letzte Woche von den New England Patriots entlassen, nachdem er nur ein Spiel gespielt hatte. Er wurde in den letzten sechs Monaten von drei Teams entlassen."

**MQM evidence**

- Four target-matched annotation rows.
- Three raters.
- One `Style/Awkward` Minor annotation for "Teams".
- One `Style/Awkward` Neutral annotation for "gespielt".
- Two No-error annotations.

**Qualitative assessment**

The word "Teams" is an English loanword commonly encountered in German sports contexts. One annotator marked it as a minor stylistic issue, while other annotations include No-error. This is an example of annotation variation rather than clear evidence of a translation failure.

The phrase "von drei Teams entlassen" conveys the main idea that Brown was released by three teams during the stated period.

**Interpretation:** A low-severity stylistic observation with explicit No-error evidence from other raters. It should not be treated as a critical translation problem.

## 4. Cross-case findings

The ten cases reveal several recurring patterns.

### 4.1 Minor errors can contribute to high model rankings

The selected examples contain minor issues involving lexical choice, fluency, awkward phrasing and literal translation. These issues may contribute to model scores even when the corresponding segment does not meet the operational Critical Error threshold.

This is consistent with the role of the model as a prioritization mechanism rather than an automatic error adjudicator.

### 4.2 Severity and criticality are not interchangeable

Case 2 contains a Major annotation, but its category is `Style/Awkward`. Under the project's label definition, it does not qualify as a Critical Error.

This reinforces the need to define the target label using both category and severity.

### 4.3 Annotator disagreement affects interpretation

Cases 3 and 10 contain both error annotations and No-error annotations. Such disagreement indicates that not every perceived translation-quality issue is consistently assessed by all raters.

A binary label can therefore conceal differences in individual judgments and annotation granularity.

### 4.4 Target matching is necessary for reliable evidence attribution

Case 1 contains five candidate annotation rows that do not match the normalized target. Including those rows in the primary analysis would incorrectly attribute annotations from another target variant to the selected translation.

The analysis therefore uses target-matched annotations as the primary evidence and retains unmatched rows separately for transparency.

### 4.5 Repeated source segments require careful counting

Cases 3–9 represent seven MT system outputs for one source segment. This enables a useful comparison of system-specific translation behavior, but does not provide seven independent source-level observations.

The ten cases correspond to five unique source segments across four source documents: Case 1, Case 2, the segment shared by Cases 3, 4, 6, 7, 8 and 9, Case 5, and Case 10.

## 5. Implications for the Second Pair of Eyes system

The findings support three practical conclusions.

First, a high model score should be interpreted as a review-priority signal, not as proof of a critical translation error.

Second, the system's false positives may still contain useful information about minor translation-quality problems. A human reviewer can decide whether these issues deserve attention under the available review budget.

Third, the model and the MQM label definition serve different purposes. The model ranks segments based on learned patterns, while the operational label defines which errors count as critical. Their disagreement is therefore an important object of analysis rather than something that should be hidden.

## 6. Limitations

This analysis has several limitations.

1. The ten cases were selected from the highest-ranked LR_Base development predictions and are not a random sample.
2. All ten cases have `y_primary = 0`; therefore, this analysis does not characterize model behavior on true positive cases.
3. Seven cases share one source segment, limiting source-level diversity.
4. Five candidate annotation rows do not match the selected target and are excluded from the primary annotation interpretation.
5. MQM annotations represent human judgments and may contain disagreement.
6. The independent linguistic observations in this report are qualitative assessments by the project team, not a separate expert adjudication.
7. No conclusion about generalization to unseen languages, domains, or MT systems can be drawn from these ten cases.

## 7. Conclusion

The qualitative analysis shows that high-ranked non-critical predictions are not necessarily error-free translations. Several contain minor accuracy, fluency or stylistic issues, while others show annotator disagreement or no-error judgments.

The findings highlight an important distinction between identifying translation-quality weaknesses and detecting operationally defined Critical Errors. The Second Pair of Eyes system should therefore be positioned as a human-in-the-loop prioritization tool. Its purpose is to help reviewers decide which segments to inspect first, not to replace human judgment or automatically declare a translation incorrect.

The analysis is based on the current authoritative ten-case selection and uses only target-matched MQM annotations as primary annotation evidence. All unmatched annotations are retained separately for auditability.

# G4.2 – Error Analysis Synthesis

## 1. Purpose and Scope

This report synthesizes the quantitative and qualitative error-analysis findings from the WMT 2020 MQM English–German dataset. It connects the experimental results from Week 10 with the qualitative analysis from Week 11 to examine the limitations of reference-free Critical Error Detection (CED).

The analysis focuses on five aspects:

1. False-positive taxonomy among high-priority Dev segments.
2. MQM annotation uncertainty and target-matching limitations.
3. Model limitations and ablation findings.
4. Operational implications under a fixed 20% review budget.
5. Threats to validity and directions for further evaluation.

The analysis does not treat every segment selected by the ranking models as an actual translation error. In particular, a segment containing a Minor MQM annotation is not necessarily a Critical Error under the project's label definition.

## 2. False-Positive Taxonomy

### 2.1. Analysis population

The Dev set contains 1,554 segments. The top 20% review budget corresponds to 311 segments. Among these, 180 segments received zero serious votes and were selected for further investigation.

All 180 selected segments were matched to MQM segment keys. At the segment-key level, each segment had annotations from three distinct raters, resulting in 540 segment-rater records.

After strict target matching, 893 of the 959 candidate annotation rows were retained, while 66 rows referring to alternative target variants were excluded from the primary analysis. The remaining rater coverage was: 163 segments with three raters, 14 segments with two raters, and 3 segments with one rater.

The primary analysis distinguishes between segment-key matching and strict target matching. These are not interchangeable: a segment key may match while some annotation rows refer to a different target variant.

### 2.2. Segment-level MQM status

The initial segment-key-based analysis produced the following distribution:

| MQM status            | Segments | Percentage |
| --------------------- | -------: | ---------: |
| Minor_Error           |      149 |     82.78% |
| No_MQM_Error_Recorded |       29 |     16.11% |
| Minor_and_Major_Error |        2 |      1.11% |
| **Total**             |  **180** |   **100%** |

After strict target matching, the distribution changed:

| MQM status            | Segments | Percentage |
| --------------------- | -------: | ---------: |
| Minor_Error           |      149 |     82.78% |
| No_MQM_Error_Recorded |       30 |     16.67% |
| Minor_and_Major_Error |        1 |      0.56% |
| **Total**             |  **180** |   **100%** |

The strict target-matched distribution is used as the primary interpretation in this report because it more closely associates annotations with the exact translation being evaluated. The segment-key-based distribution is retained as an audit comparison.

The main finding is that most high-priority zero-vote segments still contain Minor MQM annotations. Therefore, these cases should not automatically be interpreted as completely error-free translations. Rather, they indicate that the model often prioritizes segments containing annotated errors that do not satisfy the project's Critical Error definition.

The 30 segments with no MQM error recorded after strict target matching represent false positives with respect to the observed binary label. However, the absence of a recorded MQM error does not prove that a translation is objectively error-free.

### 2.3. Major but non-critical annotations

Two segments contained Major annotations in the segment-key-based analysis:

- Online-B.1590, abcnews.363994, document 5, segment 1317.
- eTranslation.737, standard.co.uk.14516, document 1, segment 1386.

Their annotation evidence differs.

For the Online-B segment, 11 candidate annotation rows were identified, but only 6 matched the evaluated target. The Major annotation was among the unmatched rows. After strict target matching, the segment retained Minor annotations but no matched Major annotation.

For the eTranslation segment, all 3 annotation rows matched the evaluated target. Its Major annotation belonged to Style/Awkward.

Under the project's label definition, Major severity alone is insufficient to establish a Critical Error. The category must also satisfy the specified critical-category rule, and at least two distinct annotators must provide a serious vote. Style/Awkward does not meet the project's critical-category requirement.

These cases demonstrate why severity, category, target matching, and annotator voting must be considered together rather than treating every Major annotation as a positive label.

### 2.4. Annotator disagreement

Under strict target matching, 77 of the 180 selected segments exhibited annotator disagreement, corresponding to 42.78%.

The segment-key-based analysis identified 78 segments with disagreement, or 43.33%.

The strict target-matched figure is used as the primary result. The difference reflects the effect of excluding annotation rows that do not match the evaluated target.

This disagreement rate indicates that a substantial subset of high-priority segments has non-uniform annotation evidence. It should not be interpreted as Cohen's Kappa, Krippendorff's Alpha, or another chance-corrected inter-annotator agreement coefficient. It is a segment-level disagreement indicator produced by the analysis procedure.

### 2.5. Annotation-row matching limitations

The broad segment-key-based analysis identified 959 candidate annotation rows for the 180 selected segments.

After strict target matching:

- Target-matched annotation rows: 893.
- Target-unmatched annotation rows: 66.
- Unmatched segment keys: 0.

Thus, all selected segment keys had corresponding MQM annotations, but not every candidate annotation row referred to the exact evaluated target.

The 66 unmatched rows represent 6.88% of the 959 candidate annotation rows. This is a row-level matching rate, not a segment-level unmatched rate.

This distinction is methodologically important. Joining annotations using only system and segment identifiers may associate annotations from alternative target variants with the evaluated translation. Strict target matching reduces this risk.

### 2.6. False-positive taxonomy summary

The findings support the following taxonomy:

| Category                   | Interpretation                                                                                                                                        |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Minor-only errors          | The segment contains MQM errors, but they do not satisfy the Critical Error label definition.                                                         |
| No-error recorded          | No MQM error is recorded for the evaluated target. This is a false positive relative to the observed label, not proof of perfect translation quality. |
| Annotator disagreement     | Annotators provide non-uniform judgments, introducing uncertainty into the observed label.                                                            |
| Major but non-critical     | A Major annotation exists, but its category or voting evidence does not satisfy the Critical Error rule.                                              |
| Target-matching limitation | Some candidate annotations refer to a different target variant and must not be attributed to the evaluated translation.                               |

These categories describe different sources of uncertainty and should not be added together as mutually exclusive counts.

## 3. Model Limitations

### 3.1. Logistic Regression

On the held-out Test set, Logistic Regression achieved the highest PR-AUC among the evaluated methods:

| Model              | PR-AUC | Recall@20% | Precision@20% | Lift@20% | MCC@20% |
| ------------------ | -----: | ---------: | ------------: | -------: | ------: |
| Random             | 0.1091 |     0.1975 |        0.1016 |   0.9877 | -0.0021 |
| HeuristicRules     | 0.1391 |     0.3086 |        0.1587 |   1.5432 |  0.0920 |
| LogisticRegression | 0.1971 |     0.3148 |        0.1619 |   1.5741 |  0.0972 |
| LinearSVM          | 0.1676 |     0.2346 |        0.1206 |   1.1728 |  0.0293 |

Logistic Regression provides the strongest overall ranking performance according to PR-AUC. However, its advantage over the heuristic baseline is much smaller when evaluated at the operational review budget.

At the top 20% threshold, Logistic Regression identified 51 Critical Errors, compared with 50 for the heuristic baseline. This is an increase of only one Critical Error among 315 reviewed segments.

The paired document-cluster bootstrap used 1,000 replicates and produced the following Logistic Regression minus Heuristic differences:

| Metric        | Difference | 95% Confidence Interval |
| ------------- | ---------: | ----------------------: |
| PR-AUC        |    +0.0580 |        [0.0151, 0.1232] |
| Recall@20%    |    +0.0062 |       [-0.0880, 0.1818] |
| Precision@20% |    +0.0032 |       [-0.0525, 0.0820] |
| Lift@20%      |    +0.0309 |       [-0.4393, 0.9075] |
| MCC@20%       |    +0.0052 |       [-0.0798, 0.1376] |

Only the PR-AUC confidence interval excludes zero. The intervals for all four top-20% operational metrics include zero.

Consequently, the results support an improvement in overall ranking performance, but do not establish a statistically distinguishable advantage in the operational metrics at the fixed 20% review budget.

### 3.2. Linear SVM

Linear SVM achieved a lower PR-AUC than Logistic Regression and the heuristic baseline. It identified 38 Critical Errors in the top 315 Test segments.

Under the current feature representation and experimental configuration, Linear SVM does not demonstrate a clear operational advantage for prioritizing critical translation errors.

This conclusion is limited to the evaluated dataset and configuration. It should not be generalized to all Linear SVM applications or alternative feature representations.

### 3.3. System identity ablation

The Dev ablation compared three configurations:

| Metric        | LR Base | LR + System | System Only |
| ------------- | ------: | ----------: | ----------: |
| PR-AUC        |  0.1961 |      0.1991 |      0.1568 |
| Recall@20%    |  0.2890 |      0.2798 |      0.2523 |
| Precision@20% |  0.2026 |      0.1961 |      0.1768 |
| Lift@20%      |  1.4440 |      1.3982 |      1.2607 |
| MCC@20%       |  0.0897 |      0.0805 |      0.0527 |

Adding system identity slightly increased PR-AUC, but reduced Recall@20%, Precision@20%, Lift@20%, and MCC@20%.

The System Only configuration performed below LR Base on all five metrics. This suggests that system identity alone is insufficient to provide a strong prioritization signal.

The ablation was conducted on Dev only. Both Train and Dev contained all seven MT systems. Therefore, the results do not establish generalization to previously unseen MT systems.

### 3.4. Class imbalance and label representation

The full model dataset contains 9,926 MT segments:

- Non-critical: 8,743.
- Critical: 1,183.
- Positive rate: 11.92%.

The Test set contains 1,575 segments, including 162 positive segments, corresponding to a prevalence of approximately 10.29%.

This class imbalance makes Accuracy insufficient as the primary evaluation measure. PR-AUC and review-budget metrics are more relevant to the project's ranking objective.

The qualitative analysis also shows that the binary Critical/Non-critical label does not represent the full range of MQM annotation information. Minor errors, Major errors outside the critical-category definition, and annotator disagreement are not fully represented by the binary target.

## 4. Operational Implications

The intended application is a decision-support system that ranks machine-translated segments for human review under a limited review budget.

On Test, the 20% review budget corresponds to 315 of 1,575 segments.

| Ranking method     | Critical Errors in top 315 |
| ------------------ | -------------------------: |
| Random             |                         32 |
| HeuristicRules     |                         50 |
| LogisticRegression |                         51 |
| LinearSVM          |                         38 |

Both Logistic Regression and the heuristic baseline improve over random ranking.

Logistic Regression identifies one additional Critical Error compared with the heuristic baseline. Although Logistic Regression has a higher PR-AUC, this small difference at the operational cutoff does not establish a substantial practical improvement.

The heuristic baseline therefore remains a useful, transparent, and computationally simple reference method. Logistic Regression remains a promising candidate because of its stronger overall PR-AUC, but its operational value requires further validation.

The proposed Second Pair of Eyes system should be used to:

1. Generate a priority queue of segments for human review.
2. Help reviewers allocate limited time toward segments with higher predicted critical-error risk.
3. Provide a decision-support signal rather than an automatic quality judgment.
4. Preserve human responsibility for final translation-quality assessment.

The system should not automatically reject translations or replace professional human evaluation.

## 5. Threats to Validity

### 5.1. Construct validity

The Critical Error label is operationally defined using MQM category, severity, and a minimum of two serious votes from distinct annotators.

This definition provides a reproducible target, but it does not capture every possible interpretation of translation quality. Results are conditional on the project's label definition.

### 5.2. Annotation validity

The strict target-matched analysis found disagreement in 77 of 180 selected zero-vote segments.

This indicates uncertainty in a substantial portion of the qualitative analysis population. The study does not report a chance-corrected inter-annotator agreement coefficient for this subset.

### 5.3. Data-linkage validity

The analysis identified 66 target-unmatched annotation rows among 959 candidate rows. Segment-key matching alone is therefore insufficient to guarantee that every annotation belongs to the exact target being evaluated.

Strict target matching is necessary when interpreting qualitative error evidence.

### 5.4. External validity

The experiments use WMT 2020 English–German data, seven MT systems, and 130 documents.

The results do not establish generalization to other language pairs, domains, datasets, or unseen MT systems.

### 5.5. Statistical validity

The Test set contains only 20 document clusters. Although document-cluster bootstrap is used to account for document-level dependence, the resulting confidence intervals remain broad for several top-20% metrics.

The findings should therefore be interpreted as evidence from a limited held-out evaluation rather than definitive proof of operational superiority.

### 5.6. Random baseline comparability

The Dev random baseline averages 100 rankings, whereas the Test random baseline uses one ranking with seed 20261026.

The random baseline therefore has different levels of Monte Carlo averaging across the two evaluation stages. This should be considered when comparing random-baseline values between Dev and Test.

## 6. Overall Synthesis

The experimental results indicate that classical machine-learning models can provide useful ranking signals for reference-free Critical Error Detection.

Logistic Regression achieved the highest PR-AUC on the held-out Test set, outperforming the heuristic baseline and Linear SVM. However, its operational advantage under a fixed 20% review budget was marginal: it identified only one additional Critical Error compared with the heuristic baseline.

The paired document-cluster bootstrap showed a statistically distinguishable improvement in PR-AUC, but did not establish an advantage in Recall@20%, Precision@20%, Lift@20%, or MCC@20%.

The qualitative analysis further showed that many high-priority segments without critical votes still contained Minor MQM annotations. A substantial proportion also exhibited annotator disagreement. These findings suggest that the binary Critical Error label does not fully represent the range and uncertainty of translation-quality annotations.

The analysis also demonstrated that strict target matching is important. Annotation rows associated with alternative target variants can affect the interpretation of segment-level error evidence if they are joined only by segment identifiers.

Overall, the Second Pair of Eyes system should be considered a decision-support mechanism for prioritizing human review rather than an autonomous translation-quality evaluator. Further validation on additional language pairs, domains, and unseen MT systems is required before making broader generalization claims.
